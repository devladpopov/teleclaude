<h1 align="center">TeleClaude</h1>

<p align="center">
  <strong>Telegram-форум, в котором каждый топик становится отдельным AI-агентом: Claude Code или любая OpenAI-совместимая модель через OpenCode.</strong><br>
  Изолированные сессии, постоянная память, runner, переживающий падения, и автономный Director. Всё работает на вашей машине.
</p>

</p>

TeleClaude превращает Telegram-супергруппу с топиками (режим форума) в рабочее пространство для нескольких проектов с AI-агентами: по умолчанию [Claude Code](https://docs.anthropic.com/en/docs/claude-code), либо любая OpenAI-совместимая модель через [OpenCode](https://opencode.ai) (см. [Провайдеры](#провайдеры)). Каждый топик привязан к своему каталогу проекта и своей сессии агента. Вы пишете или наговариваете голосовое в топик, и в каталоге проекта запускается `claude -p` с загруженной памятью и правилами. Агент работает с файлами, терминалом, браузером и MCP-серверами и отвечает в тот же топик.

Данные принадлежат вам. Память проектов, чекпоинты, правила, история сессий и браузерные профили лежат обычными файлами на вашем диске. Модель становится заменяемой частью: смена провайдера или способа авторизации это одна настройка, и работа продолжается с того же `CHECKPOINT.md`. Как авторизоваться, см. [Условия провайдеров](#условия-провайдеров).

## Ваши данные

Всё, что знает TeleClaude, лежит обычными файлами на вашем диске:

| Что | Где |
|-----|-----|
| Память и правила проекта | В папке каждого проекта: `VISION.md`, `SOUL.md`, `topic-memory.md`, `CHECKPOINT.md`, `CLAUDE.md` / `AGENTS.md` |
| Общая память | `main-memory.md` и `TELECLAUDE_MEMORY_DIR` (по умолчанию `~/.teleclaude/memory`) |
| Карта топиков и id сессий | `config/topics.json` |
| Настройки, провайдеры, режимы авторизации | `config/*.json`; ключи в файлах, на которые вы указываете (принято `~/.teleclaude/secrets`) |
| История сессий | Claude Code: `~/.claude/projects`; OpenCode: `~/.local/share/opencode` |
| Логи задач | `runner/data/jobs` |

Для бэкапа или переезда на другую машину скопируйте корень проектов, `config/`, `~/.teleclaude` и обе папки сессий, затем установите TeleClaude и поправьте пути проектов в `config/topics.json`, если они изменились. Отдельной команды бэкапа пока нет.

## Как это работает

```
Telegram-супергруппа (режим форума)
|
+-- Топик "Backend API"   -> claude -p --resume <id>  (cwd: ~/Projects/backend-api/)
+-- Топик "Лендинг"       -> claude -p --resume <id>  (cwd: ~/Projects/landing/)
+-- Топик "DevOps"        -> claude -p --resume <id>  (cwd: ~/Projects/devops/)
+-- Новый топик           -> каталог проекта создаётся из templates/
```

Один топик равен одной изолированной сессии:

- **Свой рабочий каталог.** Для нового топика создаётся папка проекта из `templates/` (`CLAUDE.md`, `SOUL.md`, `VISION.md`, `topic-memory.md`, ссылка или копия `main-memory.md`).
- **Настоящее продолжение сессии.** Роутер хранит реальный id сессии Claude Code (UUID) для каждого топика в `config/topics.json` и передаёт его через `--resume <session-id>`. Флаг `--continue` не используется, поэтому сессии разных топиков не смешиваются.
- **Мьютекс на топик.** Сообщения внутри одного топика обрабатываются строго по очереди, два `--resume` одной сессии одновременно не запускаются. Разные топики работают параллельно, в пределах `processes.maxConcurrent`.
- **Память на каждом запуске.** `--append-system-prompt` не сохраняется между `--resume`, поэтому роутер собирает его заново при каждом вызове: `VISION.md`, `SOUL.md`, `topic-memory.md`, `main-memory.md` и, при необходимости, `contextFiles` из общего каталога памяти. Блок ограничен примерно 6,5 тыс. символов, чтобы не упереться в лимит командной строки Windows.
- **Дисциплина чекпоинтов.** Правила в системном промпте требуют вести `CHECKPOINT.md` в корне проекта (`STATUS`, `TASK`, `LAST_ACTION`, `NEXT`, `DO_NOT_REDO`, `VERIFY_BEFORE_ACT`) и читать его первым делом после сжатия контекста. Этот же файл читает Director.

## Возможности

| Область | Что есть |
|---------|----------|
| Маршрутизация топиков | Один топик = один каталог проекта и одна сессия Claude Code с `--resume` |
| Память | `VISION.md` + `SOUL.md` + `topic-memory.md` + `main-memory.md` на каждом запуске, плюс общий каталог долговременной памяти |
| Runner | Отдельный процесс владеет запусками `claude`, поэтому рестарт роутера не убивает работающие задачи |
| Director | Регулярный скан `CHECKPOINT.md` всех топиков, реестр и дашборд в JSON, автотриггер застрявших топиков с кулдаунами, режим план-выполнение-проверка, зависимости, утренняя сводка |
| Делегирование между топиками | MCP-инструмент `trigger_topic`: агент одного топика передаёт работу другому |
| Провайдеры | Claude Code или любая OpenAI-совместимая модель (DeepSeek, Qwen и другие) через OpenCode; `/provider` для каждого топика, без рестарта, сессии хранятся по исполнителям |
| Авторизация | Режимы `/account` для Claude: `apikey` (рекомендуется) или ваш собственный вход в Claude Code (`default`, `token`, `configDir`) |
| Модели | `/model` и `/effort` для каждого топика; каждый ответ помечен тегом модели, например `[opus-5.5]` |
| Планирование | Повторяющиеся задачи `/loop`, напоминания `/remind`, `reminder-mcp`, чтобы агент сам ставил себе follow-up |
| Пул браузеров | Свой браузерный контекст на топик через брокер и выделенные профили Chrome для отдельных топиков |
| Медиа | Голос и аудио через локальный Whisper, видео (транскрипт + кадры через ffmpeg), фото, документы |
| Хук базы знаний | Необязательный, по умолчанию выключен. Если включить, текст каждого сообщения отправляется на ваш собственный эндпоинт базы знаний |
| Экстрактор в реальном времени | Необязательный, по умолчанию выключен. Если задан `GEMINI_API_KEY`, текст сообщений отправляется в Google Gemini API, а найденные факты сохраняются в память |
| Вывод | Потоковая отправка блоков в Telegram, разбиение длинных сообщений без разрыва code-блоков, статус-heartbeat при долгих вызовах инструментов |
| Эксплуатация | Защита от второго экземпляра, эндпоинт `/health`, необязательный режим webhook, восстановление зависших сообщений «думаю...» после падения |

## Архитектура

```
                 +----------------------+
                 |  Telegram Bot API    |
                 +----------+-----------+
                            | long-poll или webhook (/webhook + secret token)
+---------------------------v-----------------------------------------------+
| Router (Bun + grammY)                                 HTTP 127.0.0.1:7885 |
|  - фильтр allowedUsers, режимы групп (active / mention-only)              |
|  - топик -> проект (config/topics.json)                                   |
|  - сборка system prompt: VISION + SOUL + topic-memory + main-memory       |
|  - команды: /model /effort /account /loop /remind /vision ...             |
|  - медиа: Whisper, кадры ffmpeg, загрузка фото и документов               |
|  - Director (тик раз в 15 минут, 0 токенов) + утренняя сводка             |
|  - /internal/trigger  <-- mcp-router (trigger_topic)                      |
|  - reminders.json     <-- mcp-reminder (schedule_reminder)                |
|  - опционально, выкл. по умолчанию: хук KB, экстрактор Gemini, дашборд    |
+---------------------------+-----------------------------------------------+
                            | HTTP + SSE (localhost)
+---------------------------v-----------------------------------------------+
| Runner (runner/, по умолчанию :7878)                                      |
|  - владеет процессами claude, запускает их detached с файловым stdio      |
|  - состояние задач на диске, SSE с Last-Event-ID, переживает рестарт      |
|  - idle-watchdog, лимит maxConcurrent                                     |
+---------------------------+-----------------------------------------------+
                            | claude -p --resume <id> --model <slug> --effort <level>
                            |          --append-system-prompt <память> --mcp-config <файл>
+---------------------------v-----------------------------------------------+
| Claude Code CLI, один процесс на активный топик, cwd = каталог проекта    |
|  MCP: router-mcp, reminder-mcp, playwright (через пул браузеров)          |
+---------------------------------------------------------------------------+
```

Если `runner.enabled` равен `false`, роутер запускает `claude` сам. Так проще, но рестарт роутера обрывает текущие задачи.

## Требования

- Windows 10/11 основная платформа: PowerShell-скрипты, `taskkill`, `curl.exe`, службы NSSM, задачи планировщика. На Linux и macOS роутер, runner и тесты работают (CI проверяет Ubuntu и Windows), с одним ограничением: в режиме runner команды `/cancel`, `/kill`, `/killall` и таймаут простоя останавливают задачу через `taskkill`, поэтому там задача помечается остановленной, а процесс CLI продолжает работать. PowerShell-скрипты из `scripts/` требуют Windows.
- [Bun](https://github.com/oven-sh/bun), свежий релиз 1.x.
- [Claude Code CLI](https://docs.anthropic.com/en/docs/claude-code) свежей версии с поддержкой `--effort`, с API-ключом Anthropic (рекомендуется) или с вашим собственным входом в аккаунт Claude для личного использования. См. [Условия провайдеров](#условия-провайдеров).
- Токен бота от [@BotFather](https://t.me/BotFather) и супергруппа с включёнными топиками. Бота нужно сделать администратором.
- По желанию: Node.js (для пула браузеров), Chrome, Docker с [whisper-asr-webservice](https://github.com/ahmetoner/whisper-asr-webservice) на `localhost:9000`, ffmpeg в `PATH`.

Рекомендуется API-ключ Anthropic (режим `apikey`). Ваш собственный вход в Claude Code тоже работает для личного использования, см. [Условия провайдеров](#условия-провайдеров). Другим провайдерам нужен свой API-ключ, см. [Провайдеры](#провайдеры).

## Быстрый старт

**1. Установка**

```bash
git clone https://github.com/devladpopov/teleclaude.git
cd teleclaude
bun install
cd runner && bun install && cd ..
```

Установите Claude Code CLI и проверьте в терминале, что `claude -p "hi"` отвечает: либо один раз войдите через `claude`, либо подготовьте API-ключ Anthropic для `config/accounts.json`. Для провайдеров кроме Claude установите ещё OpenCode (`npm i -g opencode-ai`), см. [Провайдеры](#провайдеры).

**2. Настройка**

```bash
cp .env.example .env                                   # TELEGRAM_BOT_TOKEN
cp config/settings.example.json config/settings.json   # allowedUsers, projectsRoot
cp config/topics.example.json   config/topics.json     # бот заполнит сам
cp config/accounts.example.json config/accounts.json   # по желанию, режимы авторизации
cp config/providers.example.json config/providers.json # по желанию, провайдеры кроме Claude
cp templates/SOUL.example.md        templates/SOUL.md
cp templates/main-memory.example.md templates/main-memory.md
```

Впишите свой Telegram user id в `telegram.allowedUsers`, а абсолютный путь к папке проектов в `projectsRoot`. В примере `accounts.json` активен режим `api` (API-ключ): укажите путь к файлу с ключом в `keyFile` или поставьте `"active": "personal"`, если пользуетесь своим входом в Claude Code. Без `accounts.json` используется собственный вход CLI.

Создайте MCP-конфиг для запусков `~/.claude/spawn-mcp-config.json` (см. [MCP-серверы для запусков](#mcp-серверы-для-запусков)). Без него агент отвечает, но без напоминаний, без `trigger_topic` и без браузера; роутер один раз пишет об этом предупреждение в лог. Отредактируйте `SOUL.md` (характер и правила общения) и `main-memory.md` (факты, общие для всех топиков). `templates/TG-RULES.md` это короткий универсальный шаблон правил оформления ответов в Telegram (стиль, абсолютные пути к файлам, таблицы, тексты для копирования). Бот показывает его по `/rules`, а краткая выжимка встроена в каждый системный промпт; поправьте его под себя.

**3. Запуск runner и роутера** (в двух терминалах)

```bash
cd runner && bun --env-file=../.env run src/index.ts   # sidecar, нужен "runner": { "enabled": true }
bun run start                                          # роутер, из корня репозитория
```

Bun читает `.env` только из текущей папки. Роутер стартует в корне репозитория и читает его сам; runner стартует в `runner/`, и чтобы он увидел `CLAUDE_RUNNER_*`, нужен `--env-file=../.env`. Порт runner роутер узнаёт из `runner/data/.runner.port`, поэтому при смене порта ничего настраивать не нужно.

**4. Работа.** Добавьте бота в супергруппу и напишите в любой топик. Роутер создаст каталог проекта и ответит там же. Новые группы регистрируются в режиме `mention-only`; переключить группу в `active` можно командой `/mode active`.

## Настройка

Все рабочие файлы `config/*.json` (настройки, топики, аккаунты, `kb.local.json`, `director-topics.json`, `browser-dedicated.json`, напоминания, повторяющиеся задачи, состояние Director) находятся в `.gitignore`. В репозитории лежат только `*.example.json`.

### config/settings.json

| Ключ | Описание | По умолчанию |
|------|----------|--------------|
| `telegram.allowedUsers` | Telegram user id, которых бот слушает. Остальные игнорируются | `[]` |
| `processes.claudePath` | Путь к Claude Code CLI | `claude` |
| `processes.opencodePath` | Путь к OpenCode CLI для провайдеров с `"executor": "opencode"` | `opencode` |
| `processes.defaultFlags` | Дополнительные флаги для каждого запуска | `["--dangerously-skip-permissions"]` |
| `processes.defaultModel` | Алиас модели, если у топика нет своей | нет |
| `processes.maxConcurrent` | Сколько процессов Claude работает параллельно | `5` |
| `processes.ttlMinutes` | Через сколько минут простоя очищается состояние процесса топика | `30` |
| `processes.idleTimeoutMinutes` | Убить запуск, если N минут нет событий stream-json | необязательно |
| `processes.heartbeatAfterSeconds` / `heartbeatIntervalSeconds` | Редактирование статус-сообщения с текущим инструментом при долгом молчании | необязательно |
| `runner.enabled` / `runner.port` | Использовать runner | `false` / `7878` |
| `browserPool.enabled` / `brokerUrl` | Свой браузер на топик через брокер | `false` / `http://127.0.0.1:8930` |
| `compaction.enabled` | Просить агента сворачивать контекст в `topic-memory.md` примерно после 15 сообщений или 30 тыс. символов | `true` |
| `memory.enabled` / `deduplication` / `revisionIntervalMinutes` | Периодическая чистка и дедупликация файлов памяти | `true` / `true` / `60` |
| `whisper.enabled` / `url` / `language` | Расшифровка голосовых | `false` / `http://localhost:9000/asr` / `ru` |
| `whisper.autoStart` / `containerName` | Поднимать Docker-контейнер Whisper по требованию через `scripts/ensure-whisper.ps1` | `true` / автопоиск |
| `projectsRoot` | Корневая папка проектов топиков | обязательно |
| `templatesDir` | Шаблоны для новых проектов | `./templates` |

Поле `runtime.paused` пишут команды `/pause` и `/resume`, поэтому пауза переживает рестарт.

### config/topics.json

Заполняется ботом. Ключи имеют вид `chatId:threadId` (`chatId:general` для топика General):

```json
{
  "groups": {
    "-1001234567890": { "name": "My workspace", "enabled": true, "mode": "active" }
  },
  "topics": {
    "-1001234567890:42": {
      "name": "Backend API",
      "project": "C:/path/to/Projects/backend-api",
      "sessionId": "3f2c1a9e-0000-4000-8000-000000000000",
      "model": "sonnet",
      "effort": "high",
      "memory": ["VISION.md", "SOUL.md", "main-memory.md", "topic-memory.md"],
      "contextFiles": ["services/servers.md"],
      "created": "2026-01-01T00:00:00.000Z"
    }
  }
}
```

`contextFiles` содержит пути относительно общего каталога памяти (`TELECLAUDE_MEMORY_DIR`). Эти файлы добавляются в промпт только этого топика.

### config/accounts.json

Режимы авторизации для `/account`. Активный режим применяется к каждому новому запуску, уже работающие процессы доделывают задачу с прежним. Используйте только свои учётные данные, см. [Условия провайдеров](#условия-провайдеров).

```json
{
  "active": "api",
  "accounts": {
    "api":      { "type": "apikey",  "keyFile": "C:/path/to/secrets/anthropic.key" },
    "personal": { "type": "default", "description": "my own Claude Code login on this machine" }
  }
}
```

| Тип | Что роутер передаёт в запуск |
|-----|------------------------------|
| `default` | Ничего. CLI использует свой вход |
| `token` | `CLAUDE_CODE_OAUTH_TOKEN` из `tokenFile`: ваш собственный долгоживущий токен из `claude setup-token`, только для личного использования |
| `configDir` | `CLAUDE_CONFIG_DIR`, отдельный каталог конфигурации CLI со своими учётными данными |
| `apikey` | `ANTHROPIC_API_KEY` из `keyFile`. Для остальных типов эта переменная удаляется из окружения дочернего процесса |

Режим нужен, чтобы переходить между провайдерами и способами авторизации, например с личного входа на API-ключ, ничего не теряя: id сессии, память и чекпоинты лежат на диске, поэтому история топика сохраняется. Когда провайдер отвечает о превышении лимита, роутер это распознаёт, а Director ставит автотриггеры на паузу до сброса окна. Лимиты пережидаются, а не обходятся.

### config/director-topics.json (необязательно)

Классификация топиков по имени для Director. Топики из `ignored` не сканируются. Топики из `communication` не триггерятся ночью. Топики из `operations` показываются как инфраструктурные.

```json
{
  "ignored": ["Песочница"],
  "communication": ["Рассылки", "Служба поддержки"],
  "operations": ["Серверы", "Мониторинг"]
}
```

### config/kb.local.json (необязательно)

Хук базы знаний необязателен и по умолчанию выключен: пока этого файла нет, он не работает. Если его включить, **текст каждого входящего сообщения отправляется во внешний сервис**, то есть на эндпоинт, который вы укажете (вашу собственную базу знаний). Каждое сообщение уходит в режиме fire-and-forget как `POST {baseUrl}/api/ingest` с bearer-токеном. Ошибки пишутся в лог и никогда не блокируют чат. Подойдёт любой сервис, принимающий такой payload (`msg_id`, `chat_id`, `thread_id`, `sender`, `date`, `text`, `msg_type`).

```json
{ "baseUrl": "http://127.0.0.1:8400", "token": "change-me" }
```

### Экстрактор в реальном времени (необязательно)

Экстрактор необязателен и по умолчанию выключен. Он создаётся, только если задан `GEMINI_API_KEY`. Если его включить, **текст сообщений отправляется в Google Gemini API**, и модель решает, есть ли в сообщении факт, решение, контакт или срок, который стоит сохранить. Найденные факты записываются в `topic-memory.md` или в общий каталог памяти. Экстрактор работает в фоне, с кулдауном на топик, и никогда не блокирует чат. Не задавайте `GEMINI_API_KEY`, если текст сообщений не должен покидать вашу машину.

### MCP-серверы для запусков

В print-режиме `claude -p` не подгружает ваши глобальные MCP-серверы. Роутер передаёт один файл через `--mcp-config` (`TELECLAUDE_MCP_CONFIG`, по умолчанию `~/.claude/spawn-mcp-config.json`), если этот файл существует. Зарегистрируйте в нём серверы из репозитория, с абсолютными путями к вашей копии:

```json
{
  "mcpServers": {
    "router-mcp":   { "command": "bun", "args": ["run", "C:/path/to/teleclaude/mcp-router/server.ts"] },
    "reminder-mcp": { "command": "bun", "args": ["run", "C:/path/to/teleclaude/mcp-reminder/server.ts"] },
    "playwright":   { "type": "http", "url": "http://127.0.0.1:8931/mcp" }
  }
}
```

Роутер передаёт в каждый запуск `TOPIC_CHAT_ID`, `TOPIC_THREAD_ID` и `REMINDERS_JSON_PATH`, чтобы эти серверы знали, какой топик обслуживают.

**Тег модели.** Системный промпт сообщает агенту точный идентификатор модели и просит начинать каждый ответ с тега вроде `[opus-5.5]`. В длинных продолженных сессиях модель иногда забывает это правило, поэтому роутер сам добавляет тег, если ответ не начинается с `[` (`ensureModelPrefix`). Алиасы сопоставляются с точными идентификаторами в `MODEL_SLUGS` в `src/config.ts`; эту таблицу нужно обновлять при выходе новой модели. У других провайдеров тег имеет вид `[<провайдер>:<модель>]`.

## Провайдеры

Топик работает с одним провайдером. `/provider` показывает текущего и кнопки, `/provider <id>` переключает топик, `/provider default` возвращает к провайдеру по умолчанию. Смена действует со следующего сообщения; идущая задача доработает как начала.

| Провайдер | Исполнитель | Подключение | Статус |
|-----------|-------------|-------------|--------|
| Claude | Claude Code CLI | API-ключ Anthropic (рекомендуется) или ваш собственный вход, см. [Условия провайдеров](#условия-провайдеров) | Агент: файлы, терминал, браузер, MCP |
| DeepSeek | [OpenCode](https://opencode.ai) | OpenAI-совместимый API, `https://api.deepseek.com/v1` | Агент через инструменты OpenCode |
| Qwen | OpenCode | Alibaba Cloud Model Studio или Cloud.ru Foundation Models, OpenAI-совместимые | Агент через инструменты OpenCode |
| YandexGPT | OpenCode | Yandex AI Studio, OpenAI-совместимый endpoint; в облаке нужен активный платёжный аккаунт | Пока не проверен |
| GigaChat | OpenCode | Только через OpenAI-совместимый прокси (например gpt2giga): сам API GigaChat не OpenAI-совместим | Пока не проверен |

Так же подключается любой другой OpenAI-совместимый endpoint. Провайдеры перечислены в `config/providers.json` (скопируйте `config/providers.example.json`), файл перечитывается при изменении:

```json
{
  "default": "claude",
  "providers": [
    { "id": "claude", "executor": "claude" },
    {
      "id": "deepseek", "executor": "opencode", "name": "DeepSeek",
      "baseURL": "https://api.deepseek.com/v1", "model": "deepseek-chat",
      "apiKeyEnv": "DEEPSEEK_API_KEY", "keyFile": "secrets/deepseek.env"
    }
  ]
}
```

- **Ключи.** `keyFile` это `.env`-файл с переменной из `apiKeyEnv`; относительные пути считаются от `TELECLAUDE_HOME` (по умолчанию `~/.teleclaude`), поэтому ключи лежат вне репозитория. Ключ читается при запуске и попадает только в окружение этой задачи. Собственные секреты роутера (токен бота, секрет вебхука, учётные данные Claude, ключи других провайдеров) из окружения задач не-Claude удаляются, а runner не хранит окружение на диске после старта.
- **Та же память, те же правила.** `VISION.md`, `SOUL.md`, `topic-memory.md` и правила чекпоинта приходят в OpenCode файлом инструкций рядом с `AGENTS.md` проекта. Каждый ответ помечен реальным провайдером и моделью, например `[deepseek:deepseek-chat]`.
- **Сессии по исполнителям.** `config/topics.json` хранит сессию Claude в `sessionId`, а сессии других исполнителей в `sessions`, поэтому топик можно перевести на DeepSeek и обратно, и оба диалога продолжатся. `/reset` начинает заново для всех.
- **Лимиты.** Ошибка 429 или квоты у любого провайдера обрабатывается как лимит Claude. Director ставит на паузу только топики этого провайдера до сброса окна, топики на других провайдерах продолжают работать. Сам TeleClaude провайдера не меняет, это всегда ваша команда `/provider`.
- **Требования.** `opencode` в `PATH` (`npm i -g opencode-ai`) или `processes.opencodePath` в `config/settings.json`, и `runner.enabled: true`: другие исполнители работают только через runner.
- **MCP.** Серверы из `spawn-mcp-config.json` (напоминания, `trigger_topic`, браузер) для каждой задачи переводятся в конфиг `mcp` OpenCode, поэтому работа между топиками и напоминания ведут себя так же. В OpenCode инструменты называются `<сервер>_<инструмент>` (например `router-mcp_trigger_topic`).

## Director

Director это модуль внутри роутера (`src/director.ts`), вызовы LLM ему не нужны. Раз в 15 минут он:

1. Читает `CHECKPOINT.md` каждого проекта из карты топиков и разбирает статус, прогресс, подзадачи и `NEXT`.
2. Пишет `config/director-registry.json`, `config/director-dashboard.json` и журнал событий `director-events.json`. По желанию выгружает их на статический хостинг по SSH (`src/dashboard-sync.ts`, переменные `DASHBOARD_SYNC_*`).
3. Находит застрявшие топики в статусе `IN_PROGRESS` и автотриггерит их: короткое уведомление в топик, затем обычный запуск с просьбой продолжить с `NEXT`.

Защита от зацикливания:

- только чаты из `DIRECTOR_ALLOWED_CHATS`;
- лимит триггеров за тик, базовый кулдаун 2 часа (30 минут для `PRIORITY: high`), адаптивное удвоение, если триггер не дал прогресса (до 24 часов), и дневной бюджет на топик;
- лимит подряд идущих автотриггеров, который сбрасывается, когда в топик пишет человек;
- жёсткий чёрный список, чтобы топик Director никогда не триггерил сам себя;
- ночное окно (с 22:00 до 08:00 по Великобритании) для топиков `communication`, переопределяется полем `BLOCKED_AT_NIGHT`;
- пауза по лимиту: после ответа о превышении лимита автотриггеры ждут сброса окна;
- быстрый повтор через 5 минут, если runner сообщает, что последняя задача упала, вышла по таймауту или замолчала.

Поля чекпоинта, которые понимает Director:

```
STATUS: IN_PROGRESS            # IN_PROGRESS | COMPLETED | STALLED | AWAITING_USER | DEFERRED
TASK: Перенести вебхуки биллинга
PROGRESS: 60
NEXT: Написать интеграционные тесты для повторных попыток
PRIORITY: high                 # high | normal | low
AUTO_MODEL: opus               # модель для автотриггеров (по умолчанию sonnet)
EXECUTION_MODE: pev            # simple | pev
BLOCKED_BY: -1001234567890:42  # ждёт, пока тот топик станет COMPLETED
BLOCKS: -1001234567890:43      # зависимые топики будятся после завершения этого
ARCHIVED: false
DO_NOT_REDO:
  - миграция 0042 уже применена
VERIFY_BEFORE_ACT: git log -1
```

**Режим PEV** (`EXECUTION_MODE: pev`) работает в три фазы: Opus пишет файл плана, Sonnet (или `AUTO_MODEL`) его выполняет, Opus проверяет. Если проверка не прошла, задача возвращается на выполнение с обратной связью. С `VISUAL_VERIFY: true` и `VISUAL_URL` добавляется визуальная фаза: страница открывается в браузере, найденные проблемы вёрстки исправляются (до 3 итераций).

**Утренняя сводка.** Раз в день, около 08:00 по Великобритании, Director отправляет сводку состояния топиков в `DIRECTOR_SUMMARY_TOPIC`: активные топики, завершённые за сутки, ожидающие пользователя и отложенные из-за rate limit.

**Глубокие аудиты** выполняются обычной работой агента. Типичный вариант: отдельный топик Director с повторяющейся задачей вроде `/loop 4h проверь все чекпоинты и пришли отчёт`. Группировка топиков в кластеры с целями и KPI тоже делается в markdown-файлах этого топика. Это приём использования, а не встроенный код.

## Работа между топиками, напоминания и циклы

- **`trigger_topic(topicKey, text)`** (`mcp-router`) позволяет агенту запустить работу в другом топике. Обычное сообщение бота в чужой топик отсеялось бы фильтром `allowedUsers`, поэтому инструмент вызывает локальный эндпоинт роутера `/internal/trigger`. Путь тот же, что у Director. `current_topic()` возвращает `topicKey` вызывающего топика.
- **`/loop 6h <текст>`** сохраняет повторяющуюся задачу в `config/recurring.json`. Интервал от `1m` до `30d`. На каждом срабатывании в топике запускается Claude с этим текстом.
- **Напоминания.** `/remind` и инструменты `reminder-mcp` (`schedule_reminder`, `list_reminders`, `cancel_reminder`) пишут в `config/reminders.json`, а срабатывают они в роутере. Напоминание может быть простым сообщением или запуском Claude в топике. Напоминания, созданные, пока роутер лежал, сработают после его подъёма.
- **Напоминания обычным текстом.** Сообщение, которое начинается с «напомни ...» или "remind me ...", превращается в `/remind`. Сообщение, которое начинается со времени («через 2 часа ...», «в 9 ...», «завтра ...», "in 2h ..."), становится запланированным запуском Claude (`/remind --do`): ответа сейчас не будет, задача выполнится в указанное время. Если нужен ответ сразу, начните сообщение с чего-то другого.

## Пул браузеров

Без пула все топики делят один Chrome и перехватывают друг у друга активную вкладку. С `browserPool.enabled` runner на каждую задачу запрашивает браузер у брокера (`scripts/browser-pool-broker.ts`, `127.0.0.1:8930`) и пишет MCP-конфиг топика, в котором подменён только адрес `playwright`.

- По умолчанию каждый топик получает свой процесс браузерного MCP (`browser-mcp/server.mjs`) с изолированным контекстом в общем Chrome с выполненными входами (CDP) и копией cookies этого профиля. Вкладки разделены, а логины продолжают работать.
- Выделенные профили: для отдельных топиков можно поднять собственный Chrome с отдельным `user-data-dir` и CDP-портом, без общих cookies. Так входы разных проектов хранятся в отдельных браузерных профилях.
- Ограничения: до 16 браузеров топиков одновременно, остановка после 60 минут простоя, очистка осиротевших процессов после нештатного выхода.
- Любая ошибка брокера откатывает запуск на статичный MCP-конфиг, так что пул не может сломать обычную работу чата.

Зависимости браузерного MCP ставятся один раз командой `cd browser-mcp && npm install`. Их всего два, обе с зафиксированной версией: `@modelcontextprotocol/sdk` 1.29.0 и `playwright-core` 1.63.0. Выделенные профили задаются в `config/browser-dedicated.json` (скопируйте `config/browser-dedicated.example.json`). Каталог профилей по умолчанию `~/.teleclaude/browser-pool` (`BROWSER_POOL_PROFILE_ROOT`), профиль общего Chrome бота по умолчанию `~/.teleclaude/browser-profile` (`BOT_BROWSER_PROFILE`). Порты и путь к Chrome заданы константами в начале файла брокера; поправьте их под свою машину. Подробности в `scripts/README-browser-pool.md`. Chrome, запущенный из службы, живёт в невидимой сессии, поэтому браузерные демоны удобнее запускать задачами планировщика при входе в систему, если окно нужно видеть (например, чтобы один раз залогиниться).

## Медиа: голос, видео, фото, документы

| Вход | Обработка |
|------|-----------|
| Голосовые, аудио, видеокружки, аудиофайлы | Отправляются в локальный Whisper. Транскрипт сохраняется в `<проект>/transcripts/` и передаётся агенту текстом. Если контейнер лежит, его поднимает `ensure-whisper.ps1` |
| Видео | Звуковая дорожка через Whisper плюс равномерно нарезанные кадры через ffmpeg (`src/video-frames.ts`), которые агент читает как картинки. Без ffmpeg агент всё равно получает файл и транскрипт |
| Фото | Самый крупный размер скачивается в `.tmp/`, агент открывает его инструментом Read |
| Документ | Скачивается в `.tmp/` и передаётся агенту по пути. `scripts/setup-document-skills.ps1` умеет ставить скиллы для PDF, DOCX, XLSX и PPTX (сам пакет в git не входит) |

## Запуск как службы Windows

Роутер и runner рассчитаны на работу в виде служб Windows под NSSM (Non-Sucking Service Manager). Вспомогательные скрипты ожидают имя службы `ClaudeRouter`:

```powershell
nssm install ClaudeRouter "C:\path\to\bun.exe" "run src/index.ts"
nssm set ClaudeRouter AppDirectory "C:\path\to\teleclaude"
nssm set ClaudeRouter AppEnvironmentExtra "DIRECTOR_ALLOWED_CHATS=-1001234567890"

nssm install ClaudeRunner "C:\path\to\bun.exe" "--env-file=..\.env run src/index.ts"
nssm set ClaudeRunner AppDirectory "C:\path\to\teleclaude\runner"
```

Полезные скрипты в `scripts/`: `doctor.ps1` (проверка здоровья с кодами выхода), `mcp-health-watchdog.ps1`, `playwright-mcp-daemon.ps1`, а также `setup-cloudflared.ps1` и `set-telegram-webhook.ps1` для режима webhook через туннель. Роутер пишет lock-файл `.router.pid` и завершается, если уже работает другой экземпляр. Это избавляет от конфликтов 409 в Telegram.

## Разработка

```bash
bun install && (cd runner && bun install)
bun run typecheck   # src, runner/src и тесты
bun test            # unit- и интеграционные тесты, без Telegram и без настоящих CLI
```

Всё внешнее в тестах замокано: Telegram Bot API отвечает локально, runner заменён локальным HTTP-сервером, а CLI claude и opencode заменены маленькой скомпилированной программой, которая воспроизводит записанный вывод (`runner/test/fixtures`). CI (`.github/workflows/ci.yml`) запускает то же самое на Ubuntu и Windows.

## Безопасность

TeleClaude даёт ИИ-агенту доступ к терминалу вашей машины. Прочитайте этот раздел до запуска.

- **Белый список.** Обрабатываются только сообщения от `telegram.allowedUsers`. Сообщения других пользователей и ботов (включая сам TeleClaude) игнорируются.
- **`--dangerously-skip-permissions`.** Пример настроек передаёт этот флаг, потому что подтверждать вызовы инструментов в терминале некому. Агент может читать, писать и запускать всё, что доступно вашему пользователю Windows. Используйте отдельную учётную запись или машину, делайте бэкапы и пропишите правила (что требует явного подтверждения: платежи, удаления, публикации) в `SOUL.md` и глобальном `~/.claude/CLAUDE.md`. Правила в промпте снижают риск, но не убирают его. Флаг можно убрать и полагаться на проверки самого CLI, но тогда в автономном режиме большинство вызовов инструментов будет отклоняться.
- **Секреты не попадают в репозиторий.** `.env`, `config/settings.json`, `config/topics.json`, `config/accounts.json`, `config/kb.local.json`, напоминания, логи и стартовые скрипты с токенами находятся в `.gitignore`. Токены аккаунтов и API-ключи читаются из файлов, на которые вы указываете, и не хранятся в `accounts.json`.
- **Гигиена окружения.** `ANTHROPIC_API_KEY` удаляется из окружения дочернего процесса, если активный режим не `apikey`.
- **Локальные порты.** Роутер (`7885`) по умолчанию слушает только `127.0.0.1` (`ROUTER_BIND_HOST`), runner (`7878`) слушает `127.0.0.1` (`CLAUDE_RUNNER_HOST`), брокер браузеров (`8930`) слушает только `127.0.0.1`. Runner принимает задачи без аутентификации, поэтому держите его на loopback. Через `/internal/trigger` можно запустить работу в любом топике, поэтому эндпоинт принимает запросы только с loopback-адреса, отклоняет любой запрос с заголовком `cf-connecting-ip` или `x-forwarded-for` (то есть всё, что пришло через туннель или прокси), а если задан `ROUTER_INTERNAL_SECRET`, требует совпадающий заголовок `x-router-internal-secret`. Для дополнительной защиты закройте входящие подключения к этим портам в брандмауэре Windows. В режиме webhook публикуйте через туннель только `/webhook` и задайте `ROUTER_WEBHOOK_SECRET`.
- **Приватность необязательных интеграций.** Обе выключены по умолчанию. Хук базы знаний (`config/kb.local.json`) отправляет текст каждого сообщения на указанный вами эндпоинт. Экстрактор в реальном времени (`GEMINI_API_KEY`) отправляет текст сообщений в Google Gemini API. Без них текст сообщений покидает машину только через сам Telegram и через Claude Code.
- **Рамки Director.** Автотриггеры ограничены чатами из `DIRECTOR_ALLOWED_CHATS` и лимитами, описанными выше.

## Условия провайдеров

TeleClaude это независимый проект с открытым кодом, он не связан с Anthropic или другими провайдерами моделей, не одобрен и не спонсируется ими. Роутер запускает немодифицированный Claude Code CLI или OpenCode CLI, и каждый запрос уходит с вашей машины под вашими собственными учётными данными, поэтому условия провайдера действуют напрямую для вас:

- Anthropic: [Claude Code: legal and compliance](https://code.claude.com/docs/en/legal-and-compliance), [Consumer Terms](https://www.anthropic.com/legal/consumer-terms) (Free, Pro, Max), [Commercial Terms](https://www.anthropic.com/legal/commercial-terms) (API, Team, Enterprise), [Usage Policy](https://www.anthropic.com/legal/aup).
- Любой другой подключённый провайдер моделей: его собственные условия.

Что это значит на практике:

- **Рекомендуемый режим: API-ключ** из [Claude Console](https://platform.claude.com/) или от поддерживаемого облачного провайдера (режим `apikey`). Именно такую авторизацию Anthropic предполагает для инструментов и автоматизации поверх Claude.
- **Вход по подписке** (режимы `default`, `token`, `configDir`) допустим только для вашего личного использования Claude Code на вашей собственной машине и на ваш риск. Лимиты Pro и Max рассчитаны на обычное индивидуальное использование, а автономная работа вроде автотриггеров Director может выходить за эти рамки.
- **Один человек, свои учётные данные.** Не передавайте, не объединяйте, не ротируйте, не перепродавайте и не одалживайте аккаунты и токены. Если настраиваете TeleClaude другому человеку, он входит своим аккаунтом или со своим API-ключом; вы не собираете и не храните его учётные данные.
- **Лимиты соблюдаются, а не обходятся.** Когда провайдер отвечает о превышении лимита, TeleClaude ставит работу на паузу и ждёт сброса окна. Смена провайдера всегда ваше решение (`/provider`), а не автоматическая реакция на лимит.
